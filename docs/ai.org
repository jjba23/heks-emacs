* =ai.el=
Configures AI-assisted development in Emacs: GPTel answers a prompt about what is at point, and ECA is the chat that reads and edits the project.  Both talk to either of two accounts, and which one a session uses is not written into the checkout: ~auto~ takes a DeepSeek key -- in ~DEEPSEEK_API_KEY~ or in the encrypted file described below -- as the personal account and GitHub Copilot as what is left, ~HEKS_AI_PROVIDER~ (or ~heks/ai-provider~) names one outright, and ~C-c x p~ moves the session to the other account without a restart.  The Copilot login is GPTel's and ECA's own.

ECA's server is started in the background, so that a chat opens at once rather than seconds after the key was pressed, and it is started quietly: no window and no message, because nobody asked for either yet.  There is no project to prepare at startup -- this Emacs is a daemon, started in a directory that belongs to none -- so what is prepared is the project of the first file visited in one, once; an Emacs started with ~emacs .~ has its project already and is prepared at its first idle moment.  The chat buffer is made at that point, so ~C-c x t~ toggles a chat rather than showing the current buffer, and the first chat one opens is the one that shows itself.  ~heks/ai-eca-prepare~ turns this off and ~heks/ai-eca-prepare-delay~ says how soon it happens.

* Storing the DeepSeek key
The key belongs nowhere near this checkout.  It is looked for in three places, in this order, when a request is made rather than when Emacs starts: ~DEEPSEEK_API_KEY~, the file named by ~heks/ai-deepseek-key-file~ (by default =~/.config/heks/deepseek.key.gpg=), and an auth-source entry for =api.deepseek.com=.  A file whose name ends in =.gpg= or =.asc= is decrypted with GPG; any other file is read as it is, which is convenient but not what this configuration recommends for a key that outlives the machine.  Nothing found is an error that names all three, rather than a request that leaves without a key and comes back as a 401.

The environment variable is not the recommended place, even though it works.  Emacs here is a daemon started by the compositor, so a line in =~/.profile= never reaches it; and what is exported to the daemon is inherited by every process it starts -- language servers, shells, and the commands an AI chat runs -- and is readable by any process of the same user through =/proc=.  A key file is read only when a request needs it.

Encrypt the key once to the GPG key already on the machine:

#+begin_src sh
mkdir -p ~/.config/heks && chmod 700 ~/.config/heks
umask 077
read -rsp 'DeepSeek API key: ' dsk; echo
printf '%s\n' "$dsk" | gpg --batch --yes --trust-model always \
  -e -r jjbigorra@gmail.com -o ~/.config/heks/deepseek.key.gpg
unset dsk
chmod 600 ~/.config/heks/deepseek.key.gpg
#+end_src

~read -rsp~ keeps the key out of the shell's history, ~umask 077~ and the final ~chmod~ keep it out of other users' reach, and ~--trust-model always~ is what lets ~gpg --batch~ use a key with no ownertrust set -- the usual state of one's own key on a fresh machine.  ~-r~ takes any selector GPG knows, so a mail address from the key works as well as the key id ~gpg --list-secret-keys~ prints.

Check that it decrypts, without printing it (mine for example gives 36):

#+begin_src sh
gpg --batch -q -d ~/.config/heks/deepseek.key.gpg | wc -c
#+end_src

Rotating the key is the same command again over the same file: nothing in the configuration refers to the key itself, only to the file's name.

ECA does not read that file through this configuration -- it is not an Emacs package -- so its own config names the same file as the source of its key, in =~/.config/eca/config.json=:

#+begin_src json
{
  "providers": {
    "deepseek": {
      "api": "openai-chat",
      "url": "https://api.deepseek.com",
      "key": "${cmd:gpg --batch -q -d $HOME/.config/heks/deepseek.key.gpg}",
      "models": {
        "deepseek-flash": {},
        "deepseek-v4-pro": {}
      }
    }
  }
}
#+end_src

DeepSeek has a provider in ECA, but not one of the endpoints it ships by default: =api= names the protocol it speaks, =url= the endpoint, and =models= the model names this configuration asks for.  Without =url= ECA stops a chat with "API url not found", and without =models= it has no =deepseek/deepseek-flash= to offer.  ~${cmd:...}~ is run through a shell, so ~$HOME~ is expanded.  Logging in with ~/login deepseek~ instead writes the key into that JSON file as plain text, which is the thing this section is trying to avoid.

An auth-source entry in =~/.authinfo.gpg= -- =machine api.deepseek.com login apikey password ...= -- is the third place, and the natural one if a machine already keeps a netrc there.  ECA cannot read that format, so the key file above is what serves both tools.

A key file that exists is also what ~auto~ takes as the sign that this machine is the personal one, so no environment variable is needed for that either.  On a machine without one, ~auto~ chooses Copilot; ~HEKS_AI_PROVIDER~ or ~heks/ai-provider~ overrides the choice either way.
