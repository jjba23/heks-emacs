*[Unreleased]*

*** Added
- Broke the README into pages that can be read on their own, each linked from it: =docs/installation.org= for the requirements, the two installs, the first start, the five-minute tour and what to do when something is not right; =docs/configuration.org= for every customization variable and the bridges; =docs/themes.org= for the palettes; =docs/modules.org= for every module in its own words; =docs/ai.org= for GPTel, ECA, the two accounts and how the DeepSeek key is stored; and =docs/development.org= for the checks a contributor runs. The README keeps what a landing page is for -- what it is, what you get, the numbers, the key scheme and the documents -- and links into the rest.
- Added =docs/onefetch.org=, the documentation of the onefetch module: the fleet's screen and how a block stays the program's own output, every key of both screens, onefetch's own options in the menu, the settings, how a remote becomes the page =b= opens, what is remembered and when, and the design notes and troubleshooting.
- Added to =onefetch.el= the screen of one repository: ~C-c w O~ asks onefetch about the project of the buffer it is pressed in -- or the block of the fleet's screen point is in, or a checkout picked from a prompt, with ~C-u~ for a directory of one's own -- and draws it in a buffer named after it, with the same mode and the same keys. There is no reading to wait for: the commit it is at is one ~git~ call and the description is asked for in the background as the fleet's are, kept in the same cache by directory, commit and arguments, so a repository described on one screen is on the other at once. The header names the repository rather than counting them, ~g~ asks about that one and keeps the others' descriptions, and the keys that would do nothing with one -- the order, the filter -- are not offered. A directory that is not in a repository is refused rather than shown as a failure.
- Added =onefetch.el=, which shows every repository of mine as [[https://github.com/o2sh/onefetch][onefetch]] describes it, in one buffer. ~C-c w o~ asks the program about each checkout under ~heks/onefetch-directories~ (~~/Hacking~ by default) -- the languages and how much of each, the authors, when it started, its last change, its commits, the churn of its files, its lines of code, its size, its licence and its URL, beside the piece of ASCII art its main language is drawn as -- and puts the answers one under the other, a block per repository, in the order of their names or of the last change. What is in a block is onefetch's own output, character for character: the escape codes that colour it are turned into faces on the text, so the colours are the program's rather than an imitation of them, and nothing is reimplemented that could drift away from the tool it shows. What the module adds is the screen, and it waits for nothing: the window is drawn in a millisecond, one process walks the directories and asks git for the commit each checkout is at while the screen is being read, and the repositories are described as the answers arrive, ~heks/onefetch-parallelism~ at a time -- so a checkout with a million commits is a block that arrives a few seconds late rather than a window that does not open. What was described in the session is remembered by directory, commit and arguments, ~g~ asks again over the screen it is showing rather than after emptying it, changing an option mid-fill gives up on the answers that were being fetched instead of mixing them with the new ones, and closing the buffer stops the work. Every key the buffer has is its own: ~n~ and ~p~ walk the repositories, ~TAB~ folds the block point is in and ~S-TAB~ folds every one, ~RET~ opens it in Magit, ~o~ in Dired, ~b~ the page its remote names (an ssh alias resolved through ~ssh/config~, since ~git@personal.github.com~ is a name only ssh knows), ~s~ changes the order, ~f~ shows only the repositories whose name matches, and ~m~ is onefetch's own options -- the art, the palette, the title, bold, ISO dates, bots and merges, the number of authors and languages and churned files, and which of the seventeen fields to leave out -- in a menu, because a flag is a thing to try rather than a setting to write down. The module list in ~init.el~ gains ~onefetch~, ~C-c w o~ is described in the key scheme, and the tests hold the three things it can get wrong: that a record read from a pipe is a record and not half of one, that the directories are read in the background and the screen opens before them, and that a description already got is not asked for twice.
- Added =github-repo.el=, which keeps a repository's GitHub configuration in this configuration and gives it to the next one. It is the Emacs Lisp of the shell script that lived in the heks-linux checkout (~scripts/github-repo.sh~ with its settings in ~github-repo-settings.json~), and the JSON went with it: the settings are the value ~heks/github-repo-spec~, a JSON object is an alist, a JSON ~false~ is ~json-false~ and a JSON ~null~ is ~nil~, because a setting that is off is not a setting that is absent. ~M-x heks/github-repo-capture~ reads a repository -- the general and merge settings, ~security_and_analysis~, private-vulnerability reporting, Actions permissions, the default workflow permissions and every ruleset -- and shows the result as a ~defconst~ form in a buffer of its own, or writes it to a file with a prefix argument; ~M-x heks/github-repo-apply~ creates the repository if it is not there, renames a Codeberg ~origin~ to ~codeberg~ and adds the GitHub one (with the alias from ~/.ssh/config~ or the ~gh~ token, whichever the protocol is), pushes the default branch and its tags, and then applies the settings one field per request in dependency order, the security features one per request so a paid-only one cannot block the others, and the ruleset -- dropping the Copilot, code-quality and code-scanning rules, and the extra-approval parameter, that the plan or the repository refuses, one per retry and with a warning for each. ~M-x heks/github-repo-verify~ captures the live repository, normalizes it (when it was captured and the order GitHub answers in are not settings) and shows the difference as a diff. A prefix argument on ~apply~ makes it say what it would do instead of doing it. It is one module and no keys: these are run once per repository, they ask questions, and the three commands are ~M-x~ commands. Nothing has to be installed beside ~gh~ -- the script's ~jq~ and ~bash~ are what it was ported to be rid of -- and the spec of the reference repository ships with the module. The module list in ~init.el~ gains ~github-repo~, the settings are documented in ~docs/github-repo.org~, and the tests hold the port to the three things it can get wrong: that a ~false~ setting is sent as ~false~, that a ruleset the plan refuses loses one thing per retry, and that the capture time and the key order are not differences. It is general enough for the repositories it has not met yet: ~heks/github-repo-spec= is the house style and =heks/github-repo-specs= holds the exceptions by owner or by repository (the most specific entry wins, an entry is a whole spec rather than a patch, and ~apply~ and ~verify~ take one as their last argument), the repository prompt defaults to the ~origin~ of the project the buffer is in rather than to a directory name, and the batch commands do the set -- ~M-x heks/github-repo-verify-all~ says ~ok~ or ~differs~ for every repository in one buffer with the diff under the ones that differ, ~M-x heks/github-repo-apply-all~ applies them one by one (a refusal is a line in the log, not the end of the others), and both leave forks and archived repositories alone unless ~heks/github-repo-include-forks~ says otherwise, since somebody else's project is not yours to standardise.
- Added =sift.el=, which is the formatter and the linter of the three Lisps this configuration edits -- Scheme, Emacs Lisp and Common Lisp -- in one program, [[https://github.com/jjba23/sift][sift]]. The editor side of it is not written here: it is the program's own Emacs package, the ~emacs/~ directory of that repository, which Elpaca installs like every other package this configuration uses. ~sift-flymake~ runs ~sift lint --stdin --format=json~ on the buffer's own text and turns each finding into a diagnostic whose text carries the rule's code (~SIFT012~) and name and whose data carries both, so the marginal note says which rule fired, ~C-c g H~ opens the page that says what it wants, and ~C-c g a~ applies *its* fix and no other's; ~sift-format-buffer~, ~sift-fix-buffer~ and ~sift-fix-at-point~ replace the buffer with the program's answer in one change group, so none of them writes a file and one ~undo~ takes any of them back. Nothing has to be saved first: the text goes to the program on standard input, or to a copy of the buffer, so an unsaved buffer is what is judged. What the module adds to the package is the drift -- the lines ~sift format~ would rewrite, which is the disagreement ~sift check~, and so a pipeline running ~sift ci~, fails a build over, reported while the code is being written rather than after it is committed -- built from the same ~heks/tool-drift-backend~ the shell and Terraform formatters come from, so it runs asynchronously and touches nothing; and the keys, in this configuration's grammar rather than the package's. The package's ~sift-mode~ is turned on, because it is what puts sift's commands in a buffer, but its keymap is not the package's: the ~C-c s~ prefix is taken out of it -- ~C-c s~ is the snippets topic here -- and the three actions are given the letters the scheme already promises, ~C-c g a~ the fix of the rule reported at point, ~C-c g A~ every fix, ~C-c g H~ the page that says what the rule wants. A minor mode's map answers in every buffer the mode is on in, so those three keys work in Emacs Lisp and Common Lisp as well as in Scheme, where before they were the Scheme buffer's alone; and the mode's own before-save hook is replaced by this configuration's, so the dialects formatted on save are still ~heks/sift-format-dialects~ rather than whatever the mode is on in. Formatting keeps the keys it had: ~C-c i f~ in every buffer sift formats, and ~C-c g f~ in a Scheme buffer, where the fallback to Emacs' own indentation lives. The rest of the package's prefix -- ~sift-lint~, ~sift-ci~, ~sift-check-buffer~, ~sift-format-region~, ~sift-code-actions~ -- stays ~M-x~ commands: the questions they ask are answered by the drift, by ~C-c i f~ and by the language server's own actions, and a letter invented for them would be a key the scheme cannot describe. What is checked is sift's answer rather than a list of opinions of this configuration's own -- ~sift list-checkers~ prints the rules with their codes, dialects and severities, ~M-x sift-explain~ prints the page of a rule by name -- and a project that wants a different threshold says so in its own ~sift.yaml~, which the editor reads because sift reads it. The module list in ~init.el~ gains ~sift~.
- Added to =sift.el= the settings that make the program reachable and the findings worth reading. The settings of the program itself are the package's, so what is set is what it reads: ~sift-executable~ (the ~sift~ on the ~PATH~, or the launcher of a checkout, so a machine where sift is only a checkout still gets it), ~sift-lint-severity~ (everything by default; nil passes nothing and lets the project's own ~sift.yaml~ decide, which is what the package learned to do rather than to pass a default of its own), ~sift-format-on-save~, ~sift-format-style~, ~sift-comment-align~ and ~sift-extra-arguments~. The two that are this configuration's own are ~heks/sift-format-dialects~ (Scheme alone, since sift's idea of how an Emacs Lisp file is laid out is its own), and ~heks/sift-lint-flymake~ and ~heks/sift-format-flymake~, which say whether the findings and the drift are reported at all. Where sift is not installed nothing of it is registered and a Scheme buffer is what it was: the Guile compiler and ~guix lint~.
- sift is also registered as the language server of the three Lisps: ~sift lsp~ is what Eglot connects to for Scheme, Emacs Lisp and Common Lisp, in all five modes they open in, so ~M-x eglot~ -- or ~C-c i e~ -- in one of them now finds sift. Its diagnostics are the findings of ~sift lint~, the code actions it offers are sift's own fixes, and ~textDocument/formatting~ is ~sift format~. The contact is the sift package's (~sift-eglot-contact~), so the server is the same program the Flymake backend runs and the same one a build runs, down to the fallback to the checkout. What the server does not send is formatting findings, so ~heks/sift-drift-backend~ keeps reporting the drift; and what would be said twice is said once -- when the server is sift, ~sift-flymake~ stands aside (the check reads the command Eglot started), and it is put back when the server shuts down, so one finding is one note whichever half of sift is reporting.
- Added ~notes-graph.el~ and ~notes-graph.html~: ~C-c n g~ shows how the notes connect as a smooth, interactive map in the browser -- a force-directed graph of the links between notes, of the topic tree, or of both, with search, a neighbourhood highlight, an inspector panel, an archive toggle and a collapsible tree tab -- served by a loopback-only, token-protected HTTP server inside Emacs, so a double-click on a note opens it in Emacs. ~C-c n T~ shows the topics and notes as a folding outline in a buffer, and ~C-c n G~ exports the map as one self-contained HTML file. The module list in ~init.el~ gains ~notes-graph~, and the page is installed with the modules.
- Documented the whole note taking setup in ~docs/notes.org~: the reasoning behind plain files, the layout and every file format, each workflow (capture, find, link, move, today, habits, contacts, bookmarks), index pages, syncing, setup and migration, settings, design notes and an FAQ. The terminal side is documented in cask-and-cons (~docs/notes-from-the-terminal.org~).
- Added the personal side of the notes, integrated with the agenda. ~contacts.el~: ~contacts.org~ in the notes directory holds contacts as headings with ~:EMAIL:~, ~:PHONE:~ and ~:BIRTHDAY:~ properties; ~C-c n k~ finds one with the details beside the name (a prefix inserts ~Name <email>~), ~C-c n K~ adds one, an address in a message is completed from them, and every birthday is in the agenda through the one line ~%%(heks/contacts-birthdays)~ in ~birthdays.org~. ~bookmarks.org~ stays the start page it was: ~C-c n b~ picks a bookmark (category and host beside it) and opens, copies or inserts it, ~C-c n B~ files the URL at point, in the browser or in the kill ring under a category chosen with completion. ~agenda.el~: ~C-c n x~ captures a todo into ~todo.org~ from anywhere, linked to where it came from, ~C-c n X~ captures a habit (a todo with an ~.+1w~-style repeater, drawn as a graph by ~org-habit~ in ~habits.org~), ~C-c n d~ is today (the day with its habits and birthdays, what is in progress, the inbox), ~C-c n h~ the habits and ~C-c n u~ the birthdays coming up. Big notes, ~bookmarks.org~ and ~contacts.org~ are kept out of the agenda files.
- Index pages are generated: every topic folder's ~index.org~ is rebuilt between ~# BEGIN GENERATED INDEX~ and ~# END GENERATED INDEX~ from the notes in it, on saving a note, on creating or moving one, with ~C-c n I~, or from a shell with ~emacs --batch -f heks/notes-regenerate-indexes~. What is written above the markers stays, an index with no markers is never touched, and a page is only written when it changed.
- Eglot starts by itself in the three Lisps. The four modes a Scheme, Emacs Lisp or Common Lisp file opens in (~scheme-mode~, ~scheme-ts-mode~, ~emacs-lisp-mode~ and ~lisp-mode~) are on ~heks/eglot-ensure~, which is the switch every other language here uses, so opening one of those files is what connects it to ~sift lsp~ -- the server ~sift.el~ registers for them -- rather than a ~M-x eglot~ per project: completion, hover, the server's diagnostics, its code actions, its formatting and its definitions answer from the first command in the buffer. A Lisp *data* file is not one of the four, though the server is registered for it too: what is in one is data, and a jump to the definition of a name is not a question a file of data answers. ~C-c i e~ is what a buffer no hook reached is given by hand, and ~C-c i 0~ still turns every server off, since the switch is the same function in every mode.
- ~M-.~ falls back when the language server has nothing to say. ~xref~ asks one backend and takes its answer, including no answer: a server that cannot resolve a name -- a definition in a file it has not indexed, a macro of the language, a module it does not know -- used to be the end of the jump, with the backends the buffer already had never asked. =dev-folding.el= gains ~heks/xref-backend~, which is put in front of the server's own entry while the server manages the buffer and asks, in order, the server first and then every backend the buffer had (the Scheme backend of ~guile.el~ with its REPL and its files, the Emacs Lisp one, ~dumb-jump~, a tags table), so the narrower the answer the earlier it is asked and a name the server does not know is still a name the files can find. ~M-?~ and ~M-s .~ are answered the same way, since it is the same backend. The entry is buffer-local and is added and taken out with the server, so a buffer without one jumps exactly as it did, and nothing is replaced: the server's answer simply stops being the only one. The name the fallbacks search for is read by the buffer's own tool rather than by the server -- Eglot reads the name at point only when it is about to ask which one is meant, and otherwise answers with a stand-in, since it asks the server about the place point is at -- so what ~dumb-jump~ and the rest are given is a name and not a stand-in.

*** Changed
- A start no longer stops at the first line of =early-init.el= that a build without a window system cannot run.  ~tool-bar-mode~ is not defined in Guix's ~emacs-no-x~ -- the daemon the compositor starts, and the build this configuration was started in for a while -- and ~scroll-bar-mode~ is not defined there either, so the unguarded calls ended the file at that line: the GC threshold, ~inhibit-startup-screen~ and ~native-comp-speed~ below them were never set, and every start of that daemon printed the error.  The three calls are guarded with ~fboundp~ now, so the settings under them are the ones a session gets whichever build it is.
- Onefetch's menu no longer loads ~transient~ with the module.  It was the only thing in this configuration that wanted it at startup, and asking for it there made Emacs load its own =transient.elc= while the modules were being read -- ahead of the build Elpaca installs, which Elpaca reported on every start as "transient loaded before Elpaca activation".  ~m~ now goes through ~heks/onefetch-options~, which requires it the first time the key is pressed and then opens the same menu; the key is in ~heks/onefetch-mode-map~ with the rest of the screen's keys and is still named in the header, and a start with no screen opened loads nothing of it.
- =guile.el= no longer formats or checks a Scheme buffer with ~guix style~: sift does both (see =sift.el= above), on a machine with Guile and nothing else, and in the three dialects rather than one. The dependency on Guix is gone from formatting, from the drift diagnostics and from the keys: ~C-c g f~ formats with sift, ~C-c g a~ applies the fix of the rule under point, ~C-c g A~ every fix and ~C-c g H~ explains that rule, where ~C-c g S~ used to apply one of ~guix style~'s styling rules to a saved file and reload it. What Guix is still the authority for is what only Guix knows -- ~guix lint~ on a package (~C-c g L~), the Guix REPL, Emacs-Guix's own bindings -- and the Guile compiler is still what says whether a file is sound.
- The Guile compiler and ~guix lint~ are no longer all a Scheme buffer has. A file that defines no package, or a machine with no Guix, used to be checked by the compiler alone; the habits of the file -- the rules it is read with -- are sift's now, and the compiler's findings sit beside them rather than instead of them.
- The prompts over the notes are quick to type in. ~C-c n f~, ~C-c n F~, ~C-c n i~, ~C-c n r~ and ~C-c n s~ used to read the head of every note twice for every keystroke -- once to make the candidate, once to annotate it -- because nothing was remembered between them. Three caches now stand between a prompt and the disk: the list of files, what each file's head said (checked against the note's modification time and size, so a note edited elsewhere is still read again), and the topic folders with their counts. A prompt asks the disk once and then answers from memory; the annotations of a row, which are asked for on every refresh, cost a hash lookup each. The caches are thrown away by the configuration itself when a note is created (~C-c n n~, ~C-c n c~), moved (~C-c n r~) or saved, and by ~M-x heks/notes-cache-clear~; ~heks/notes-cache-seconds~ (5 by default) says how soon a file that arrived from somewhere else -- a sync, a shell command, another editor -- is noticed, and setting it to ~0~ scans on every use, which is what this used to do. Measured on 400 notes: the candidate list 45 ms cold and 6 ms warm, 400 annotations 0.2 ms rather than a file read each, and the topic table for ~C-c n n~ 19 ms cold and 0.01 ms warm. Hidden folders are no longer walked at all rather than walked and then filtered out, so the archive is not scanned for a prompt that will not offer it, and the topic prompt no longer offers ~.archive~ at the top of the list. ~C-c n s~ falls back to ~deadgrep~ when Consult is not there, rather than to ~lgrep~.
- The hover popup is quick to appear and cheap to keep around. It waited for *every* source to answer (or for ~heks/hover-timeout~) before showing anything, so a language server that had already answered was held behind the slowest one; the first answer is now shown at once and the popup is updated as the others arrive. The timer that follows the pointer no longer looks anything up while the pointer has not moved and the window under it has not scrolled, which is what most of its ticks are. A popup showing the same words as the one before it is not rendered and measured again, so hovering along a line of names no longer re-lays out a document per symbol. ~heks/hover-delay~ goes from 0.4 to 0.3 seconds and ~heks/hover-timeout~ from 0.8 to 0.6, the latter now bounding how long the request listens rather than how long a popup takes to appear.
- Notes carry no identifiers any more: a note is ~#+title:~ and ~#+date:~, and links between notes are relative ~file:~ links. Moving a note with ~C-c n r~ rewrites the links that pointed at it and makes the links inside it relative to where it now is.
- Renamed every function, variable, face, group and feature from ~heks-emacs-NAME~ to ~heks/NAME~ (and private ~heks-emacs--NAME~ to ~heks/NAME~), through the modules, tests, README and the key reference. The settings are still accepted under their old ~heks-emacs-~ names, as obsolete aliases, so a bridge written before the rename keeps working until it is regenerated. File names (~heks-emacs.el~, the ~test/heks-emacs-*.el~ files) and the project name are unchanged.

*** Removed
- Removed =scheme-lint.el=, and ~heks/scheme-lint-check~ with it: the habits of a Scheme file are sift's rules now (see =sift.el= above), which are the same idea written once, maintained as a program rather than as a module of this configuration, and read from the three Lisps rather than one. Two checkers with two opinions about the same form is how a person learns to ignore both, so the module, its registration and its tests are gone rather than left beside the one that replaced them. The ~heks/scheme-lint-~ settings are gone with it, and so is the reader it carried: what reads the buffer is the program a pipeline reads it with.
- Removed the last use of ~guix style~ in this configuration: ~heks/guix-style-flymake~, ~heks/guix-style-rules~, ~heks/guix-style-backend~, ~heks/guix-style-apply-rule~ (and ~C-c g S~, which was its key) and ~heks/guix-fmt~, a command that formatted the buffer with ~guix style -f~ and that nothing in the configuration bound. Formatting a Scheme file is sift's business now; what remains of Guix in =guile.el= is what only Guix can answer.
- Removed ~org-roam~ and ~org-roam-ui~ altogether. Notes are now one Org file each in topic folders, with no database (see ~notes.el~): ~heks-emacs-notes-roam-dir~ is now ~heks-emacs-notes-dir~ (the old name still works as an obsolete alias), ~heks-emacs-import-into-roam~ is ~heks-emacs-import-into-notes~, an import writes the standard ~:ALIASES:~ property rather than ~:ROAM_ALIASES:~, and the daily-note and graph keys are gone.

*** Added

- Added ~C-c n M~ (~heks-emacs-markdown-region-to-org~), which converts the Markdown in the region to Org in place, for the piece of a document one has in a buffer rather than the file ~C-c n m~ imports. It is a piece rather than a note, so it says things the way an imported note does -- a bullet is ~-~, a fence a source block, a link an Org link -- but makes no title out of a leading heading, writes no property drawer and leaves every heading at the level it has (~heks-emacs-markdown-fragment-to-org~ is the string it is made of). With a prefix argument, or in a buffer that cannot be written to -- a chat, a help buffer -- the Org goes on the kill ring and the buffer is left as it is, which is the way to take Markdown from somewhere one cannot edit into a note.
- Added =scheme-lint.el=, which points out the bad practices of Scheme that work and should not be written, as Flymake diagnostics beside the line that has the habit. The Guile compiler and ~guix lint~ say whether a file is *sound* and say nothing about the code that runs; this says what a reader would say, and it needs nothing installed, because it is Elisp over the buffer rather than a tool being run. It reads the buffer with a reader of its own -- positions included, so that a diagnostic sits on the form that is wrong rather than on the line it started on -- and holds it to twenty-odd rules: a name bound twice by one ~let~ or one procedure, a clause after a ~cond~'s ~else~, ~eq?~ asked of strings, numbers or characters, ~=~ asked of a string, a definition with no value, ~define-macro~, ~nil~, a ~begin~ in a body that is already a sequence, an empty ~begin~, a one-armed ~if~ with a ~begin~ in it, ~(if c #t #f)~, an eta-reduction that ~map~ already does, ~(apply f (list a b))~, a car/cdr composition five deep, ~(reverse (reverse x))~ and its round trips, ~(set! x x)~, an ~assoc~ on a symbol key, and the two things a Guix package does that ~guix style~ would unlearn -- old-style labelled inputs, and ~#:tests? #f~. A rule that fires on code that is fine is a rule that gets the checker turned off, so the test suite holds every one of them to the forms around it that must *not* be reported: a quoted ~nil~ is data, a comment is not code, and a file that stops in the middle is still checked as far as it was read.
- Added =duplicates.el=, which finds the code a project writes more than once and reports it where a person will read it. The scan reads the files the project says it has, normalizes every line, drops the blank ones and the comment-only ones, indexes every window of six consecutive lines, extends the windows that appear twice as far as the two copies agree, and keeps the runs that are long enough, appear more than once, and are not a piece of a longer run with the same places. ~C-c v D~ shows the result in a buffer of its own, worst first: how many lines, in how many places, how many of them written twice; a button per place that opens the file with the clone lit up; the first lines of the block as an excerpt; ~n~ and ~p~ to walk the clusters, ~s~ to show the copies inside one file as well -- hidden by default, because a block copied within a file is a function waiting to be written and the same block in two files is the one nobody notices -- and ~g~ to scan again. What it finds is text that repeats spelled the same way: a copy whose variables were renamed is not found, which is the honest limit of a comparison that needs no parser and no index, and it is the kind that catches what actually happens. Run against this checkout it finds five clusters, the largest being a block that ~render.el~ and ~import.el~ share -- which is the reading of a document they are supposed to share, and worth seeing said twice.
- The Markdown preview now reads what a document has since Markdown was written down: reference-style links and images, resolved from the ~[label]: url~ line that defines them (which is a definition rather than a paragraph); footnotes, numbered in the order the notes are *read* and answered at the end of the page with a link back to each marker; GitHub's callouts, ~> [!WARNING]~ rendered as a box that says what kind of quote it is; task lists as the checkboxes a reader of one expects; ~==highlight==~; ~:emoji:~ shortcodes; backslash escapes, so an escaped asterisk is an asterisk and not emphasis; and formulas, which are transliterated to the text of them -- ~$E = mc^2$~ is ~E = mc²~, ~\alpha \leq \beta~ is ~α ≤ β~ -- rather than fetched as a typesetting library, because a preview that needs a network is a preview that shows no formula on a train. A fenced block is labelled with the language it is, tables stripe their rows, the contents list keeps its own box, and the page is printed with callouts and code blocks kept whole. The note an import writes is held to the same reading: a reference link is the link it names, a callout is imported as the sentence it carries rather than as the marker that introduced it, and a definition line is not a paragraph of the note.
- Added ~C-c r s~ (~heks-emacs-preview-sync~), which moves the preview of a document to the section point is in -- the nearest heading above point in the Markdown or Org file, looked for by its text in the page being shown. It asks a different question from the jump: not where a name is, but which names there are that match a pattern -- a name half remembered, a family of names, a fragment of one -- and where each of them is, and both of the sources this backend has answer it. The files of the project are searched for the heads of their definitions, and the name each head defines is read out of it and matched here, in Emacs, against the pattern read the way Emacs reads one (~xref-apropos-regexp~: a regexp, or a list of words that all have to appear), so one search answers a pattern of any kind and what an entry shows is the head itself -- the name, the arguments, the body, which is the signature that makes a list of matches worth reading. The REPL answers with the names it has loaded, which is the half no search of this project can give: the names of Guile's own and of the libraries the project uses are names defined in files this project does not hold. A name both sources answer for is offered once, with the files' answer, since the files know the line the head is on; a name only the REPL has arrives as the name, under the heading ~the REPL~, and where it is is asked of the REPL when it is jumped to -- the question ~M-.~ asks, so the jump lands on the head that defines it -- rather than once for every name of a list one is reading, and a name the REPL cannot place (a procedure written in C, say) is a jump that says so rather than one that lands wherever the name was searched for.   - ~C-c g r~ starts or switches to the current project's REPL (a Guix REPL in a buffer that defines packages, a plain Guile one elsewhere), with the project root on Guile's load path and one REPL per project. ~C-c g R~ restarts it and ~C-c g s~ points it at the module of the current buffer.
  - Evaluation, loading and interruption from the buffer: ~C-c g e~ (definition at point), ~C-c g E~ (region or buffer), ~C-c g b~ (the whole file) and ~C-c g k~. ~C-c g x~ runs the file as a script with the project root on the load path, and ~C-c g d~ returns to Geiser's debugger after an exception.
  - Navigation from Geiser's own database, so there is no language server in this: ~C-c g g~ goes to a definition, ~C-c g h~ shows its documentation, ~C-c g c~ and ~C-c g C~ list callers and callees (a call hierarchy), and ~C-c g m~ lists the methods of a generic function. ~geiser-mode~ activates itself in Scheme buffers, its completion arrives through ~completion-at-point~ (and therefore through Corfu) and ~geiser-autodoc-mode~ puts signatures in the echo area.
  - Checking on save, from whichever tool is the authority: a Flymake backend runs ~guix lint~ on the package defined in the buffer (checkers, style, and anything else the installed Guix checks), a second one runs ~guix style~ on a copy of the buffer and reports the lines it would rewrite -- in any Scheme buffer, not only in package files, since drift in a Guix library file matters too -- and a third runs the Guile compiler (~guild compile~) in every buffer Guix is not the authority for, which is where the checking comes from without Guix: unbound and unused variables, unused modules and arity mismatches. The compiler runs on a copy of the buffer, so code that has been typed but not saved is checked too. ~C-c g L~ lints the buffer into a clickable compilation buffer (the hyperlinks Guix puts around file names are turned into real ones there), ~C-c g f~ formats it in place (re-indenting it with Emacs where Guix is not installed) and ~C-c g S~ applies one of Guix's styling rules (~inputs~, ~arguments~, ~git-source~) and reloads it.
  - ~guix-devel-mode~ is enabled in Guix buffers, which brings Emacs-Guix's own bindings: ~C-c . l~ to lint, ~C-c . b~ to build the package definition, ~C-c . s~ and ~C-c . d~ for its source, and ~C-c . u~ to insert a module at point. ~C-c g t~ runs the project's own test task.
  - Folding works in Scheme: a buffer is read as top-level forms, so each definition is a fold, collapsing the definition at point works from anywhere inside it, and the keys are the ones every other language uses (~C-c v c~ folds the definition, ~C-c v o~ and ~C-c v O~ unfold it, ~C-c v r~ reveals everything, ~C-c v t~ toggles and ~C-c v C~ collapses the file).
- Added a reusable way to turn an external tool into a Flymake backend (~heks-emacs-tool-diagnostic-backend~ and ~heks-emacs-tool-drift-backend~ in ~heks-emacs.el~). A *checker* that reports diagnostics and a *formatter* whose rewrites are the diagnostics are the two shapes a language tool has, and both are now a few lines of configuration. The process runs asynchronously with a pipe rather than a pty and with colour off, because a tool that believes it is talking to a terminal wraps file names in OSC 8 hyperlinks, which hides the ~FILE:LINE:COLUMN~ structure the parsers read; the output is parsed into file, line, column, severity and message; a diagnostic the tool could not attach to a line is reported from its error output instead of being dropped; and the buffer is checked through a temporary copy, so code that has been typed but not saved counts. The Guile module's two checkers are the first users.
- Added ~render.el~, which renders what one is reading as one HTML document, themed with the colours of the current Emacs theme and with no stylesheet to download: Markdown, Org (through Org's own exporter, body only), OpenAPI specifications and plain text each have a renderer, and the document is shown in EWW with ~C-c r p~ or in the browser with ~C-c r b~. ~C-c r r~ renders it again, ~C-c r e~ keeps it as a ~.html~ file next to the one being read, and ~C-c r m~ makes the preview follow the buffer, rendering again on every save. The predicates that choose a renderer return a yes or a no rather than the position a pattern matched at, so a caller can branch on them.
- Added ~openapi.el~, which reads, checks and explains OpenAPI specifications in JSON or YAML. ~C-c a v~ renders the specification the way Swagger UI would -- operations by tag, parameters and responses in tables, schemas listed, servers named -- in the same document ~render.el~ produces, and the operations are listed in the imenu menu under their tags. The document is checked as it is written, from the same table of rules: a path that is not a path, a key under a path that is not an operation, two operations sharing an identifier, a path variable nobody declares, a response code that is not one, a response without a description, a body with no shape, and a ~$ref~ that points at nothing. Each is a Flymake diagnostic where it is written. ~C-c a r~ calls one of the operations from the file itself (the server, the method and the parameters come from the document, and the answer lands in its own buffer) and ~C-c a b~ writes it as an Org request block instead.
- Added a formatter dispatcher (~heks-emacs-format-buffer~, ~C-c i f~) so that one key formats whatever buffer it is pressed in: a language module adds a predicate and a command to ~heks-emacs-format-dispatch~ and the buffer decides. Scheme is the first user, and its formatter is the one the Guile module already had, so ~C-c i f~ and ~C-c g f~ are the same command.
- Added golden renderings: ~test/fixtures/~ holds the documents -- a Markdown note and one OpenAPI specification written both in JSON and in YAML -- and ~test/golden/~ holds the HTML they rendered to, so a change in what the renderers produce arrives as a line-by-line diff of what they say now against what they said before, rather than as an invitation to look at a page and judge it. ~maak golden~ checks it and ~maak golden-update~ writes the pages again when the change is the one that was wanted. The two spellings of the specification have one golden page between them, which is what makes the two languages having to read alike a checked property.
- Added the keybindings reference (~docs/keybindings.org~), written from the configuration by ~maak keys-update~: the alphabet of action letters, the topic letters and what every key under them does. ~maak keys~ fails while it and the configuration disagree, so it cannot go stale.
- Added ~maak lint~ and ~maak verify~, and the two scripts behind them. ~lint~ reads every Elisp file of the configuration form by form and compares the module list in ~init.el~ with the modules that are there: a parenthesis that closed a macro too early, or a module renamed without its entry in the list, fails in a second without installing anything. ~verify~ installs the configuration first and then loads it in a batch Emacs the way Emacs does at startup, asserting what nothing else checks -- that every module is loaded (the feature is read out of each module rather than guessed from its name), that the tool-output parsers read the formats they claim to, that a diagnostic renders with its message where it belongs, that a fold covers a whole definition, that the documented keys are bound, that the type scale keeps its ratios and the separators keep their colour, and that the same setup still checks Scheme where Guix is not installed. It exits non-zero on failure.  ~maak keys~ reads the source for every binding -- including the ones that only take effect when a package loads, which a runtime dump of the keymaps cannot see -- prints the whole key tree under its topic letters and fails on a key that does two jobs, on a topic nobody documented and on a binding whose command does not exist; ~maak render~ checks the Markdown renderer on its own, as the string-to-HTML function it is.  ~maak check~ runs the six of them, in that order.
- Added Guix snippets for modules (~define-module~, ~use-modules~), G-expressions and imported modules, arguments, working inside phases (~substitute*~, ~which~, ~search-input-file~), inputs in the style ~guix style -S inputs~ produces, and ~replace~ with a body.
- A rendered document now shows its code in colour and can be navigated. A fenced block is fontified with the mode the fence's language names, each face it used becomes a class, and the stylesheet carries the colours of the *current* theme for it, so a README reads like the Emacs it was written in -- a keyword is the colour of a keyword, a string the colour of a string -- and the same document is readable in a light theme and in a dark one. A snippet is escaped before it is coloured, so a ~<~ in code is still a ~<~ on the page. Every heading is given an id and a list of contents is put between the headline and the body once a document has enough sections (~heks-emacs-render-toc-headings~, three by default), which is what makes an OpenAPI page -- an operation per heading -- navigable rather than only searchable. The stylesheet ends with a print block: page margins, one deck slide per printed page, and no navigation buttons or fixed controls on paper, so what is printed is what was read.
- Added ~treesit-grammars.el~, a batch script that builds every tree-sitter grammar this Emacs can be asked for -- Emacs's own recipes being the ones its mode files add as they load, plus the recipes of the languages Emacs ships no mode for (Kotlin, Scala, Nix) -- into ~~/.emacs.d/tree-sitter~. The configuration starts it in a batch Emacs of its own at startup, in the background, so that no grammar is ever cloned and compiled while a file is being opened: with ~treesit-auto-install-grammar~ at ~always~ a missing grammar was fetched without asking, but the first file of every language made the session wait for ~git~ and a C compiler, and a language no recipe was known for was a question on every visit. Only the grammars with no library here are built, a grammar that will not build is a line in the ~*heks-emacs tree-sitter grammars*~ buffer rather than the end of the ones after it, and ~M-x heks-emacs-treesit-install-grammars~ does the same work in front of you. Cloning a repository and compiling a grammar fails for reasons that are not about the grammar -- a clone that timed out, a checkout that was busy -- so every grammar is tried ~heks-emacs-treesit-attempts~ times (twice, by default) before anything is said about it: what is reported is a grammar that would not build twice, a language that worked on the second attempt says so, and a build that returned without leaving a library Emacs can load counts as a failure rather than as a grammar, which is what Emacs's warning-not-error answer to an unloadable library would otherwise have hidden.
- An Org note now previews the way a Markdown file does, through Org's own exporter. Org is asked for the *body* of the export and nothing around it, so a note arrives in this configuration's document, with its own stylesheet and its own list of contents -- Org's own list is asked for and dropped rather than left in beside it, which is where a page ended up with two -- and the headings it names are the ones the list links to, so every entry of that list is an entry that goes somewhere. The code in a note is coloured by Org through ~htmlize~, which the configuration now installs: where it is here the colours are written into the page as inline styles, because a preview carries none of Org's stylesheet and a class name with no stylesheet behind it is a block with no colour, and where it is not, Org is asked for plain text rather than for colours it cannot produce, which it answers with a warning on every export. The settings the export runs under are bound one at a time (`let*'), because the values of a `let' are all evaluated before any of them is bound, and the export is the last of them: with `let' Org was still writing its own contents list into the body.
- Added ~present.el~, which presents what one has written. An Org note is presented in Emacs itself (~C-c r P~), where ~org-present~ narrows the buffer to one heading at a time, scales the text up and takes ~SPC~ and the arrow keys for the next and previous heading (~q~ leaves it, and the mode line is hidden while the talk lasts, because it is not part of what is being shown). Anything else -- a Markdown deck -- is presented as a page in the browser (~C-c r d~): one ~section~ per slide, walked with the arrow keys, the space bar, Home and End or two buttons, with a counter that says which slide this is and what changed when it changed, and with the address bar keeping the slide number so a reload returns to it. A deck carries its own stylesheet and its own navigation and fetches nothing, so the exported file (~C-c r D~) opens from a ~file://~ URL on a machine that is not this one. ~C-c r n~ starts the next slide where point is, in the document's own way: a line of dashes in Markdown, a heading at the level the file's own slides are at in Org.
- Added the configuration's own test suite (~test/heks-emacs-ert.el~, run by ~maak test~ and therefore by ~maak check~). The other checks read this configuration and judge what it says; this one loads the modules and calls the code, which is the only way to find out that a function does what its docstring says: the renderer (fontification, escaping, anchors, the contents list, the stylesheet a theme produces), where a deck's slides begin in Markdown and in Org, the decks themselves (one section per slide, the navigation, the print styles, the export), the JVM build tools (which goal each tool calls, the nearest project, the wrapper over the system program), the formatter dispatcher, Terraform, Dired, and the key scheme's four tables. It runs in a batch Emacs with ~use-package~ stubbed out, so what is tested is the code rather than whether a package happens to be installed, and a test that needs something this machine does not have -- the ~terraform~ program, a YAML reader -- says so and is skipped rather than failing. The suite is also what found the faults below, and it covers the preview in the shape the fault was in: the document is rendered into the preview buffer and that buffer is then looked at, because EWW kills the buffer it renders from and the difference is invisible in a screenshot of a working preview.

*** Changed

- Window separators are now derived from the active theme instead of being left at the background color, so several buffers in one frame are clearly distinguishable in every palette. The color is applied to ~window-divider~, ~window-divider-first-pixel~, ~window-divider-last-pixel~ and ~vertical-border~, it is refreshed whenever a theme or the text scale changes, and it corrects the invisible separators that ~spacious-padding~ paints on purpose.
- ~window-divider-mode~ is now enabled with 2 pixel separators on the right and 1 pixel at the bottom.
- Org, Markdown, prose and code faces are now sized as multiples of the base font size. Changing the text scale with ~tekengrootte~ no longer compounds with the ~default~ and ~variable-pitch~ faces, so headings, body text and code blocks keep their proportions at every scale.
- Opening an Org or Markdown buffer no longer resets the global text scale to the regular size.
- The face helpers in the UI module are defined at file level, so Org, Markdown and theme hooks can call them even while ~tekengrootte~ is still being installed or loaded. The same guard now protects the Eglot Java bindings, which are applied after ~eglot-java~ really loaded instead of when it was merely activated.
- SQL buffers now start Flymake so that ~sql-lint~ actually runs, instead of only being registered as a backend.
- The Scheme, Guile and Guix configuration moved out of ~dev.el~ into ~guile.el~, where the REPL engines, the checking and formatting backends and the keys live together. ~dev.el~ keeps the general-purpose development tooling.
- Geiser is now the single REPL client and is configured for project work: one REPL per project, the project root on Guile's load path, the REPL in another window, full backtraces for failing evaluations and warning levels high enough to report unused variables and unused modules, both at the REPL and in the buffer. ~geiser-mode~ now turns itself on in Scheme buffers, so completion, eldoc and the debugger are there the moment a ~.scm~ file is opened.
- Removed [[https://codeberg.org/abcdw/guile-ares-rs][Ares RS]] and [[https://github.com/abcdw/emacs-arei][arei]], together with ~heks-emacs-scheme-repl-backend~, the ~ares-nrepl~ server management and the keys that belonged to them (~C-c g a~, ~C-c g A~). Geiser covers the same workflow without a second protocol, a second session concept or a server that has to be built before the first evaluation.
- Folding is now one set of keys (~C-c v~) on top of [[https://github.com/jamescherti/kirigami.el][kirigami]], which knows which engine a buffer has -- Tree-sitter, Hideshow, Outline, Org or Vdiff -- instead of the Scheme module binding its own pair. kirigami answers with the first engine whose mode is on, and ~outline-minor-mode~ is on in almost every buffer here, so ~kirigami-fold-list~ is reordered to put Hideshow first: in the buffers where Hideshow was turned on deliberately, it is what ~C-c v c~ folds, rather than headings a Scheme file does not have.
- The key scheme now says what keeps Org's statistics cookies out of the way of the global ~C-c #~ keys: the command moved to ~C-c C-#~, which is documented as a topic of its own (~C-#~) rather than reported as an undocumented one.
- The action letter ~i~ means one thing again. It had come to mean three: ~C-c i i~ went to the implementation, ~C-c g i~ interrupted a running Guile evaluation and ~C-c s i~ inserted a snippet. ~i~ is now "insert" everywhere, and the two odd ones out moved to the letter that already means what they do -- the implementation is ~C-c i g~ in a family where ~g~ goes to a definition, and the interrupt is ~C-c g k~, where ~k~ is the letter that stops a process just as it stops a language server under ~C-c i k~.
- Two more keys moved to letters the scheme already defines: the Mermaid documentation is ~C-c C-d h~ rather than ~C-c C-d d~ (~d~ is the debugger and a diff) and Eglot reconnects with ~C-c i R~ rather than ~C-c i x~ (~x~ runs a script, ~R~ restarts, as it does for the REPL), and the methods of a generic function are on ~C-c g m~, the letter of every menu, rather than on a ~u~ that meant nothing.
- ~maak check~ now runs the configuration's own test suite as well, between the renderer's own checks and the golden renderings: ~lint~, ~keys~, ~render~, ~test~, ~golden~, ~verify~. The suite needs nothing installed -- it loads the modules out of ~src~ with ~use-package~ stubbed out -- so it is the one check that can be run while the configuration is being edited.
- EMMS is gone, and with it the music directory. The ~C-c M~ topic keyed a library, an MPD daemon and a playlist, and none of that is part of this configuration any more: ~C-c M~ is not bound at all, and ~music.el~ keeps what is about music itself -- a fretboard to look at while a chord is written down, and the player that plays the file at point -- with no library to point at, no daemon to keep running and no keys of its own under ~C-c~. The ~heks-emacs-music-directory~ setting went with them, so the line a bridge had been setting (~heks-emacs-ews-music-directory~, a name this configuration never defined) named a variable that does not exist, and nothing in the configuration reads a music directory now. ~C-c m~ is untouched: it is maak, the task runner, and it was only ever the capital letter that meant music.
- Topics that key something which is not an action no longer have to borrow an action letter for it. A font size, *whose* configuration is being reconfigured and the journal entry for today are named by their own letter in ~heks-emacs-key-letters~, and the audit now reads both tables: a key whose letters are in neither fails the build, instead of being reported as a note nobody actions. The key tree printed by ~maak keys~ shows the meaning of every key, and the whole scheme is written out as a document (~docs/keybindings.org~) from the tables and the bindings themselves, so the reference cannot stop being true while ~maak check~ is green.

*** Fixed

- Fixed the preview and the OpenAPI view, which failed with ~Wrong type argument: stringp, nil~ instead of showing anything. EWW renders a document out of the buffer its retrieval put it in and *kills that buffer* when it is done -- ~eww-render~ is the callback of a retrieval, and the buffer is the retrieval's own -- so a preview that asked EWW to render from its own destination buffer was left holding a dead one, and the ~pop-to-buffer~ that followed died on it. A preview now answers EWW the way a retrieval would (the content type, then the document, in a buffer of its own) and EWW renders that into the preview buffer, which is still there afterwards and still holds the page. ~maak verify~ asks for a preview and looks at the buffer it landed in, so this cannot come back unnoticed.
- Fixed the settings the bridge gives not reaching the modules that read them. The installed configuration defines the customization variables in ~heks-emacs.el~, gives them their values in the bridge next to it (which fonts, which theme, where the notes are) and loads the modules after that -- but the bridge was being loaded *after* the modules, so a module read a setting while it was still ~nil~ and was configured wrongly whatever the setting said a moment later. ~org-roam~ is where it showed: ~org-roam-directory~ was built out of a ~nil~ and stopped the configuration while it loaded, which is why org-roam has not worked. The bridges now load before the modules, and ~heks-emacs-notes-directory~ answers ~nil~ -- rather than a path -- when no notes directory has been set, in which case org-roam is loaded but not started and the variable to set is named in the echo area instead.
- Fixed the startup error that stopped the configuration while it loaded: ~Wrong type argument: listp, #(" ■ Warning (emacs): Duplicate item ID queued: org-present" ...)~. ~org-present~ was declared twice -- by ~org.el~ and by ~present.el~ -- and elpaca answers a package that is queued twice with a *warning string* where a queued item was expected, which the code that walks the queue then tried to read as a form. The declaration now lives only in ~present.el~, the module that presents things, and ~org.el~ says so where its own declaration used to be. ~maak verify~ loads the installed configuration the way Emacs does at startup, so a module that cannot be loaded -- and a second declaration stops the loading -- fails the build.
- Fixed the contents list of a document whose headings arrive with ids of their own. The id was kept in the page and thrown away in the list, which generated a slug out of the heading's text instead, so every link from the contents list of an OpenAPI page -- each operation named after its method and its path -- pointed at an anchor that did not exist, and following one went nowhere. A heading's own id is now the one the list points at, which is also what a link from elsewhere in the document needs.
- Fixed the document stylesheet dropping every face attribute that is not a colour. ~heks-emacs-render--face-attribute~ passed only strings and numbers through and answered ~nil~ for the rest, so the weight, the slant and the underline of a fontified face were discarded and the rules meant to carry them were written empty: highlighted code came out coloured but unemphasised, and font-lock's keyword and function-name faces lost the weight that makes them stand out. A face's attributes are now read as the face states them, so both branches of the stylesheet -- the colour and the emphasis -- are written, and a face that declares no colour still gets the plain rule that leaves it inheriting its surroundings.
- Fixed the OpenAPI renderer for YAML specifications, which came out as an empty page. ~yaml-parse-string~ hands back what a scalar *looks* like rather than what a specification means -- a bare key arrives as a symbol, so every lookup of ~paths~ or ~get~ missed and nothing was rendered, and a response written ~200~ arrives as the number 200, which stopped the rendering with ~Wrong type argument: stringp~ as soon as it was escaped. Mappings are now read once through the string their keys are written as, and everything that is shown or searched for goes through ~heks-emacs-openapi-text~, so a YAML specification and the same one in JSON render as the same page -- which is now checked, in ~maak verify~ and again as a golden rendering.
- Fixed ~required: false~, which was rendered as ~yes~: both parsers are asked for the symbol ~:false~ where a document says ~false~, and a symbol is a true value in Elisp. Booleans are read through ~heks-emacs-openapi-yes-p~, so a parameter that is not required says nothing rather than the opposite.
- Fixed the Markdown renderer leaving a list unclosed when the next block was not a list, or when the list ended the document: the closing pass only closed lists nested *deeper* than the current indentation, so a heading after an ordered list ended up inside the list. A block that is not a list now closes every list, which is what a browser does with the same document.
- Fixed the order of what the OpenAPI page shows: a mapping has no order of its own, and the one a hash table iterates in was reaching the page, so the operations, the media types of a body and the schemas could come out in a different order from one run to the next. They are read in a defined order now, which is what lets the rendering be compared with a file.
- Fixed the ~ef-autumn~ palette overrides, which were assigned to a non-existent ~ef-autumn-palettes-overrides~ variable and were therefore silently ignored.
- Fixed the ~heks-emacs-standup-people~ customization type, which warned about a ~list~ without arguments.
- Fixed a startup error in ~dev.el~: ~fancy-compilation-mode~ was called from an ~after-load~ handler for ~compile~, which fails whenever ~compile~ is loaded before Elpaca has activated the package (an early ~require~, such as Flymake's, does that). The package is now loaded on demand.
- Fixed the way diagnostics were built for Emacs 31 and later, where a diagnostic carries an origin, a code and a message rather than a bare string. A message put in the wrong slot still rendered, but with the separator of the missing headline in front of it; the tools are now named as the origin, the way Eglot names its server, so a diagnostic reads ~guix lint : ...~ and its message is the message.
- Fixed the ~C-c g l~ binding (~guix-package-location-on-mark~), which required ~guix~ and ~guix-package~ unconditionally and so failed on a machine without Emacs-Guix. It now says what is missing, and asks for a selected package name instead of reading whatever happens to be between point and the mark.
