All notable changes to this project will be documented in this file. Changes are listed per project release (tag) and within each tag there are details about changes, additions, fixes and removals.

This project adheres loosely to [[https://semver.org/spec/v2.0.0.html][Semantic Versioning]].

*[Unreleased]*

*** Added

- Added ~C-c n M~ (~heks-emacs-markdown-region-to-org~), which converts the Markdown in the region to Org in place, for the piece of a document one has in a buffer rather than the file ~C-c n m~ imports. It is a piece rather than a note, so it says things the way an imported note does -- a bullet is ~-~, a fence a source block, a link an Org link -- but makes no title out of a leading heading, writes no property drawer and leaves every heading at the level it has (~heks-emacs-markdown-fragment-to-org~ is the string it is made of). With a prefix argument, or in a buffer that cannot be written to -- a chat, a help buffer -- the Org goes on the kill ring and the buffer is left as it is, which is the way to take Markdown from somewhere one cannot edit into a note.

*** Changed

- ECA's server is no longer started by opening a chat window at startup.  The old start called ~eca~ and wrapped it in ~save-window-excursion~, which closed nothing: ~eca~ opens its chat from the callback that answers the server's ~initialize~ request, long after it has returned, so the window was opened by a call nobody was in any more.  The start is now one that says it is a start: while it lasts the chat buffer is still created and registered -- a ~C-c x t~ with no chat to toggle would show whatever buffer happened to be current -- but it is given no window, and what ECA reports while starting is not printed, because a start nobody asked for should not talk.  The first chat that is opened spends that and shows itself, and a timer gives up waiting for a server that never answers, so the chat one does ask for can never be the quiet one.  What is prepared is also right now, which it was not: the session was rooted at the directory the daemon was started in -- the home directory, for a daemon the compositor starts -- and ~eca-session~ answers with the session whose workspace folder is an ancestor, so one rooted at =$HOME= answered for every project under it and every chat ran with the home directory as its workspace.  A project is what a session is prepared for, and the earliest moment Emacs knows of one is the first file of a project that is visited: there is nothing to prepare before that, so the daemon watches ~find-file-hook~ for that file and prepares its project, once, while an Emacs started with ~emacs .~ knows already and is prepared at its first idle moment.  ~heks-emacs-ai-eca-prepare~ turns the whole thing off and ~heks-emacs-ai-eca-prepare-delay~ says how soon it happens.
- The fold indicators in the fringe are faded toward the background now, by ~heks-emacs-fold-indicator-fade~ (50 percent of the way).  They inherited ~shadow~, which most themes make as bright as a comment, and that is fine for what Hideshow and Org draw -- a marker on the line a block starts on -- and wrong for what Tree-sitter folding draws, which is a marker on every line of the block: the grey became a rule running down the fringe beside the code, most visibly in Kotlin, Lua and every other Tree-sitter mode.  The colour is the theme's own ~shadow~ blended toward the theme's own background, so a light theme is faded the other way and no theme needs an entry here; it is applied by ~heks-emacs-set-base-faces~ on every theme and scale change, and again when Hideshow and ~treesit-fold~ are loaded.
- The guide of a Tree-sitter block is a line now rather than a dashed one, and the indicators are five points brighter to pay for it. ~treesit-fold-indicators~ draws a block's guide with a bitmap 23 rows tall, centred in the line it is drawn beside; a line of this configuration is 29 pixels -- the font's 23 and the six of ~line-spacing~ -- so every row of a guide was a 23 pixel dash with three pixels of nothing above it and three below, and a block read as a dotted line rather than as a bracket, most visibly in Kotlin, Lua and the other Tree-sitter modes. The bitmaps are this configuration's now, given to the package through the string it builds for each line of a block: the guide is a single row, which ~define-fringe-bitmap~ repeats down a line however tall it is, so no ~line-spacing~ can put a gap in it, and the marker of a block and the line it ends on are cut to the height of a line, so the guide runs from the marker into the row below it and turns toward the text where the block ends. A guide drawn solid reads lighter than the same grey drawn in dashes, which is why the fade is 50 rather than 55: ~shadow~ is blended half of the way to the background instead of 55 percent of it, #444444 to #4c4c4c on a theme with #989898 shadow and a black background. The markers are cut per height, so a text scale makes new ones and ~heks-emacs-set-base-faces~ draws the indicators again with them. They stay in the fringe, where the mouse pointer is Emacs's own: the left margin would draw them as text, but ~note_mouse_highlight~ answers every margin position with the nontext cursor before it reads the string there, so a hand over a fold indicator is a change to Emacs rather than to this configuration.
- ECA's own faces are given a family now, by what they print, which is the one thing about the chat that was left in the font `default` happens to be.  The faces that name something -- the title of a chat, the label of a tool call, the three answers to one, a task, a question, the tabs, the header-line options, the settings, providers, jobs, MCP and workspaces buffers beside it -- take the sans-serif family, so a chat reads as prose; the ones that print something a reader copies out of the buffer -- a shell command, a file path, a context chip, a tool call's arguments, a keybinding, the columns of a table -- take the monospace one, which is also the family a table needs to line up.  The body of a message is neither: it is `default', and the code in it is the monospace faces Markdown already had here.  The two lists are `heks-emacs-eca-sans-faces' and `heks-emacs-eca-mono-faces' -- named rather than inferred from a face's colour, since what a face prints is not something Emacs records -- and `heks-emacs-set-eca-faces' applies them, from `heks-emacs-set-base-faces' on every theme or scale change and once more when the package is loaded, because ECA defines its faces after this module runs.  A face the installed ECA does not have is skipped rather than an error, so the lists may name a face of a version that is not installed yet.

** v1.8.3 (2026-10-15)

*** Added

- ~M-s .~ -- ~xref-find-apropos~ -- works in a Scheme buffer now, where it used to answer with the message Emacs gives when no backend has the question (~No Xref backend.  Try `M-x eglot', ...~) in a configuration that has no language server for Scheme on purpose. It asks a different question from the jump: not where a name is, but which names there are that match a pattern -- a name half remembered, a family of names, a fragment of one -- and where each of them is, and both of the sources this backend has answer it. The files of the project are searched for the heads of their definitions, and the name each head defines is read out of it and matched here, in Emacs, against the pattern read the way Emacs reads one (~xref-apropos-regexp~: a regexp, or a list of words that all have to appear), so one search answers a pattern of any kind and what an entry shows is the head itself -- the name, the arguments, the body, which is the signature that makes a list of matches worth reading. The REPL answers with the names it has loaded, which is the half no search of this project can give: the names of Guile's own and of the libraries the project uses are names defined in files this project does not hold. A name both sources answer for is offered once, with the files' answer, since the files know the line the head is on; a name only the REPL has arrives as the name, under the heading ~the REPL~, and where it is is asked of the REPL when it is jumped to -- the question ~M-.~ asks, so the jump lands on the head that defines it -- rather than once for every name of a list one is reading, and a name the REPL cannot place (a procedure written in C, say) is a jump that says so rather than one that lands wherever the name was searched for. The names are asked for with Guile's own ~apropos-internal~, named through the module it lives in rather than imported, because the module a REPL is in is ~(guile-user)~ or a project's own and is not this configuration's to change. Geiser's own completion was not what was asked, since what it answers is the names that *begin* with what it is given and a fragment of a name is a question it would answer with nothing; a list of words is asked for by its first word, with the names read against the whole pattern here, the regexp Emacs makes of a word list not being one Guile reads as meaning that.
- Made ~shellcheck~ and ~shfmt~ first-class tools for shell scripts, which is mostly about the two halves that were missing or fighting each other. Shellcheck is Emacs's own: ~sh-mode~ and ~bash-ts-mode~ register ~sh-shellcheck-flymake~, and it checks the buffer through shellcheck's JSON output, so what has been typed but not saved counts and the dialect is the one the mode decided the script is written in. Nothing had ever run it, though -- neither mode started Flymake, and the library whose other backends this configuration uses registers a shellcheck of its own and switches Emacs's off -- so a shell buffer had no diagnostics whichever tool was installed. The library's checker is now the one turned off, in ~dev.el~, and Emacs's is the one that runs; what this configuration says to it is ~--external-sources~, so the files a script ~source~s are followed and count (without it every ~source~ line is a note saying it was not followed, and the variables the sourced file sets are then reported as unassigned), and Flymake is started in both shell major modes.
- Added ~shfmt~ support, which Emacs has none of: ~C-c i f~ -- the one format key, the same in every buffer -- formats a shell buffer with ~shfmt~, and a second Flymake backend reports the lines ~shfmt~ would rewrite, the way the Guile module reports what ~guix style~ would rewrite. The formatter runs on a copy of the buffer, so drift is reported as the script is written rather than after it is saved and the buffer is never touched, and what the formatter is told is adjustable for what an EditorConfig file cannot say (~heks-emacs-shfmt-arguments~; an indentation of two spaces is the usual setting). Where ~shfmt~ is not installed the backend stays quiet and the format key falls through to whatever else the buffer has, and ~heks-emacs-shfmt-program~ names the executable where it is not on ~PATH~.
- Both of the modes Emacs opens a shell script in are covered, which is not one mode: a ~.sh~ or ~.bash~ file opens in ~bash-ts-mode~ when the bash grammar is built and in ~sh-mode~ when it is not, and a ~.zsh~ or ~.ksh~ file always does.
- Enabled ~bash-language-server~ through Eglot for shell scripts, in both of those modes -- ~eglot.el~ hooked ~sh-mode~ alone before this, so a ~.sh~ file, which comes up as ~bash-ts-mode~, never started a server at all. What it is there for is what shellcheck and shfmt cannot answer: the completion of the variables, functions and options of a script, its documentation on hover, the symbols of the file, a definition, its references and a rename. The two tools the server runs itself are turned off in it, with the empty ~shellcheckPath~ and ~shfmt.path~ that are its own way of saying "do not lint" and "do not format": shellcheck is Emacs's ~sh-shellcheck-flymake~ in every shell buffer and shfmt is what ~C-c i f~ formats with, so the server is not a second checker that would report each problem on a line twice, nor a second formatter that would quietly rewrite a script on save in a style the formatter configured here would then report as drift. Enabling a server has a second half that is easy to miss and would have made things worse than before: Eglot makes its own backend the only Flymake one for as long as it manages a buffer -- it saves `flymake-diagnostic-functions' and replaces it -- so a buffer's own checkers are added back to it when the server takes it over, and Flymake is asked to check the buffer again. Without that, turning the server on would have left every shell script checked by nothing at all. That half is now one function for every language rather than shell code of its own; see Changed below.

- Added ~markdown.el~, which is the reading of a Markdown document and nothing else: whether a line and the one after it are a table, the cells of a row, how deep a list is indented (a tab counting as four), what a code span keeps out of the rest of a line, and the directory a relative link in the document is resolved against. ~render.el~ had that reading and ~import.el~ needed it, and two readings of the same lines are two answers to the same question: the file previewed and the file imported cannot now disagree about what a table is, how deep a list is nested, or whether a paragraph with a rule under it is a level-two heading rather than a plain one. What is made of the reading -- HTML, or Org -- stays the business of the module that makes it.
- Added ~import.el~, so that a document written for other tools can become a note one works in: ~C-c n m~ (~heks-emacs-import-markdown~) imports the Markdown file of the buffer, writing the Org note next to it and leaving the Markdown exactly as it was, and with a prefix argument writes it into the notes directory as an ~org-roam~ node instead. What the note says is what the document said. The front matter becomes the keywords a note keeps its own business in -- ~#+title:~, ~#+author:~, ~#+date:~, ~#+filetags:~ with the spaces of a tag written as underscores, since Org's tags may not hold one, and a field this module has no name for as a keyword of its own name rather than something dropped, because Org keeps keywords nobody has heard of and the tool that wrote the field can find it again. The heading a document opens by naming itself with becomes that title rather than a headline repeated under it, and the headings left under it are shifted up so that the shallowest of them is a section of the note, a document written in sections and subsections otherwise being a note of subsections and of no sections at all. The rest keeps its shape and changes its spelling: headings become headlines; a bullet becomes ~-~, never ~*~, which is a headline in Org and a bullet in Markdown and no import may turn the second into the first; lists keep their nesting and ordered lists their numbers; a task list becomes the checkboxes Org reads -- ~[ ]~ and ~[X]~, since Markdown checks a box with ~[x]~ and Org reads a lowercase one as text that looks like a box, so a note that was checked would read back as a note that was not; a fence becomes a source block of the language it names and a fence with no language an example block; a quote a quote block, converted inside as the document it is; a thematic break a rule; a footnote a real footnote; and a raw HTML block an ~#+begin_export html~ block, a badge or a ~<details>~ being HTML no Org spelling improves on. Emphasis, code, links and images become Org's own markup, with a relative link resolved against the document's own directory, so that it names the file it named rather than a path that means something only from where the document used to be. A table becomes an Org table both a person and Org read: the header row, the alignment row the delimiter row declares (~<l>~, ~<c>~ and ~<r>~ cookies, which Org aligns by and keeps out of the export), the rule that closes the header -- a delimiter row is both an alignment and a rule, and without the rule Org would read the header as one more row -- and then the rows, each padded to its column so that the rule is the width of what it rules. The property drawer is written at the top of the file rather than under the keywords, which is the difference between properties Org reads and a drawer of text: a drawer is a property drawer when it is the first thing in the file, and one written under a ~#+title:~ is a drawer no ~org-entry-get~ finds. Nothing is written over unasked: a file that is there and differs is written over when the prefix argument says so or the reader says yes, and a file that already says what the import would write is written again silently. An import into the notes asks ~org-roam~ to index the note it wrote, so it is findable by ~C-c n f~ the moment it is written rather than the next time the note is opened.

*** Changed

- The Flymake checkers of a buffer now survive a language server generically, in ~dev.el~ (~heks-emacs-flymake-keep-backends~), instead of each language having to put its own back. Eglot replaces ~flymake-diagnostic-functions~ with a list of its own backend alone for as long as it manages a buffer, which is why the configuration had written a hook for shell and another for Python; what it saved is exactly what the buffer had -- whoever registered it, Emacs, a package or a module here -- so every backend of it that is not Eglot's own is added again beside the server's, and Flymake is asked to check the buffer. A module registers its checker on its major mode and says nothing about servers; a language that is not shell or Python keeps its checker for the same reason those two do, without a line about it anywhere.
- Removed the Python half of that compensation, which added Emacs's ~python-flymake~ to a buffer a server managed. What it ran was ~flake8~, which is not installed here, and ~flymake-collection~'s configuration for Python -- the one that decides what checks a Python buffer -- has already turned ~python-flymake~ off in favour of its own ~pycodestyle~ backend, so all it could do on a managed buffer was fail to find a checker and be disabled for it. A Python buffer is now checked by what checks it without a server, and keeps that when one arrives.
- ~which-key~ now shows a menu of whole sentences, in a window at the bottom of the frame, and says how many of a prefix's keys it is showing. Two things were wrong with what it did. The descriptions were cut at a round 45 characters with an ellipsis where their end had been -- ~+go to: a definition, an implementation, a location~ arrived as ~+go to: a definition, an implementation, a ..~ -- and the menu was shown in the echo area, which cannot grow past ~max-mini-window-height~, a quarter of the frame (six lines of a 25 line one), so the 29 keys under ~C-c~ arrived six at a time over five pages. The length which-key is told is now measured from the sentences the key scheme itself holds -- one more than the longest of them, because a key that opens a keymap is shown with a ~+~ in front of it, and the longest of them all is the row for ~C-c~ itself, which the old round number did not cover at all -- and the menu is a window at the bottom which is as tall as the page it holds, up to two fifths of the frame (three pages of ~C-c~ in that small frame rather than five, and one page in a larger one). Its mode line counts the keys the page holds (~WK: 10/29 keys~), so a menu that is paged says so instead of leaving one to wonder whether that was all of them, the windows that were visible get their configuration back when it goes, and the echo area is left to eldoc and to messages.
- The which-key menu is no longer lost when the frame has no room for its window. which-key makes that window by splitting the frame's main window in two and keeping one half, and asks ~split-window-no-error~ for it, whose nil answer it does not read -- so when the split is refused, which the frame's own minimum window sizes decide, the keys were written into which-key's buffer, nobody saw them, and all that was left on screen was the line the echo area carries about the menu: its title, the page it is on and ~C-h~, with no keys under it. Three windows of a 24 line frame, or two of a 16 line one, or one window of a frame shorter than nine lines, were enough. This configuration now chooses the place before the pages are made (~heks-emacs-which-key-popup-dimensions~) and shows the menu itself (~heks-emacs-which-key-show-popup~): the bottom window when the frame can be split in two for it, and the echo area when it cannot -- smaller, with the line which-key says about the menu above the keys rather than below them, but with the keys, which is the point of the menu. That is checked against ~split-window-no-error~ itself in the tests and against the real window tree in ~test/heks-emacs-verify.el~, so a change in Emacs's rule is a failing check rather than a menu that disappears again.
- Going to a definition in a Scheme buffer is now ~M-.~, the command it is in every other buffer, rather than a key of its own that did it differently. ~C-c g g~ was ~geiser-edit-symbol-at-point~, which asks the REPL: with no REPL running it stopped with ~No Geiser REPL for this buffer (try M-x geiser)~, and with one running it still stopped with ~Couldn't find location for 'greet'~ for a symbol whose module the REPL has loaded but not imported -- the usual case when reading code that has not been evaluated. What knows about Scheme is now a backend (~heks-emacs-scheme~/~guile.el~) behind ~xref-find-definitions~, so ~M-.~, ~C-x 4 .~, ~C-u M-.~, ~M-,~ and every other way of asking ~xref~ for a definition are all the same jump, improved once. The backend asks the REPL first and uses its answer when it names a file on this machine, since it is the source of the code that is running and is right about a module of Guile's or Guix's own that the project only imports; Guile's location of a procedure is a file and a line and no column, so the head that defines the name is looked for at the line the REPL named -- which is where the point lands, on the name itself rather than on the parenthesis in front of it -- and a name defined twice in a file arrives at the one the REPL was talking about. Where the REPL has no answer the files of the project are searched for the head of a ~define~ of any kind that names the symbol (a use of the name is not offered as its definition), and ~dumb-jump~'s wider search follows where the files have nothing. A name in a ~use-modules~ clause still opens the module, which is what ~M-.~ did there before.
- ~M-?~ works in a Scheme buffer now, which it did not before: it asks the REPL for the callers of the name, and where there are none to be had -- no REPL, or a module Guile has no cross-reference data for -- every file of the project that mentions the name is offered instead. Both of the jumps are the files' answers through ~xref~, so they are remembered like any other jump.
- ~M-.~ in a Scheme buffer completes from the names the project's files define, since it asks for a name when there is none at point. It is the same set of files the definitions are searched in, asked the one question that has no name in it to search for, and a name defined twice is one entry. Before this the prompt had no completions at all, which made it a question one had to answer by memory.

- Evaluating or loading in a Scheme buffer now brings the project's REPL up rather than stopping without one. ~C-c g e~, ~C-c g E~ and ~C-c g b~ needed a REPL that was already running and said so when there was none (~No Geiser REPL for this buffer (try M-x geiser)~, a message about the order one did things in rather than about the code), so the first evaluation in a fresh project was a message and a second command. The REPL started is the one ~C-c g r~ opens -- the project's, with the project root on Guile's load path, a Guix REPL in a buffer that defines packages and a plain ~guile~ one elsewhere -- started by the wanting rather than by the choosing: asking for a REPL is what an evaluation or a load is, and ~C-c g r~ stays for wanting to *be* at the prompt. A REPL that is slow to come up is waited for, bounded, so that a machine where the program is missing is told that rather than left waiting, and the buffer the command was about is kept the current one while it starts, since starting a REPL shows it and ~C-c g e~ must evaluate the definition at point in the buffer it was typed in rather than at the prompt.

*** Fixed

- Fixed a jump to a symbol Guile has and cannot place -- ~M-.~ on a procedure written in C, say -- which stopped with ~wrong-type-argument listp :f~ instead of falling through to the files of the project, and the same stop in the other two answers that carry a place: the module a ~use-modules~ clause names, and the place that goes with a caller in ~M-?~. Guile answers ~#f~ for a symbol it has and cannot place and for a caller it knows no place for, and a ~#f~ comes back through Geiser as the keyword ~:f~ rather than as nothing, which is not a location and not an empty answer either. What is read as one is now read in a single function (~heks-emacs-scheme--location-p~), and it is what Geiser's own jump reads as one (~geiser-edit--try-edit~): a location is a list, and anything else is no answer at all.

- ~fancy-compilation~ is finally doing what it was installed for: a compilation buffer shows the colours a tool asked for rather than its escape codes read as text, and the tool is told it is talking to a terminal, so it writes colours in the first place. The package was declared with ~:commands~, which is the load-it-when-it-is-called arrangement, and what it does it does by advising ~compile~, ~compilation-filter~, ~compilation-start~ and ~compilation-handle-exit~ -- so the mode had to be called *before* the first compilation, which is the one thing nobody can do in time, since the escape codes are noticed while looking at output that has already been written. A ~with-eval-after-load~ of ~compile~ was meant to answer that and could not: ~compile~ is loaded early, by Flymake among others, before Elpaca has activated the package, so the ~require~ inside it found nothing and, with ~nil~ and ~t~ for arguments, said nothing either. It is now demanded at load and turned on in ~:config~, the same way ~flymake-collection~ below it is, and ~test/heks-emacs-verify.el~ compiles something coloured and reads the colour back off the buffer, so a package that stops being turned on is a failing check rather than a line of ~[0m~ in the middle of a build log.

** v1.8.1 (2026-10-15)

*** Added

- Added Maven, Gradle and Spring Boot build commands (~heks-emacs-maven-run~, ~heks-emacs-gradle-run~, ~heks-emacs-spring-boot-run~, bound to ~C-c j m~, ~C-c j g~ and ~C-c j s~). Each one walks up from the current buffer to the closest project and prefers the ~mvnw~ / ~gradlew~ wrapper over a system-wide installation.
- Added Java, Kotlin, Terraform and SQL Tempel snippets.
- Added Kotlin support for both the classic and Tree-sitter modes, including ~.kts~ files such as ~build.gradle.kts~.
- Added Groovy support for Gradle build scripts and ~Jenkinsfile~ files.
- Added Terraform and HCL support: ~.tf~, ~.tfvars~, ~.hcl~ (including ~.terraform.lock.hcl~) and Nomad jobs, with ~terraform fmt~ on save and ~terraform-ls~ through Eglot when the toolchain is installed.
- Added SQL support through the built-in ~sql.el~: PostgreSQL is the default product, keywords are upper-cased as they are typed (~sqlup-mode~) and Flymake lints SQL when ~sql-lint~ is available.
- Added database entry points: ~heks-emacs-sql-postgres~ (~C-c d p~) opens a PostgreSQL session and ~heks-emacs-mongosh~ (~C-c d m~) opens a MongoDB shell in a real terminal buffer.
- Added Maven, Gradle, Terraform, MongoDB, SQL and Codeowners icons to Dired and the completion interfaces.
- Added a Kotlin language-server selector which uses JetBrains' ~intellij-server~, then ~kotlin-lsp~, then the community ~kotlin-language-server~, whichever is installed.
- Added Eclipse JDT LS settings to Eglot Java so that Maven and Gradle projects are re-imported automatically when their build files change.
- Added keys for Kotlin and JVM work inside Eglot Java buffers (~C-c j n~, ~C-c j r~, ~C-c j t~, ~C-c j N~, ~C-c j b~, ~C-c j B~).
- Added a ~guile.el~ module for Guile Scheme development, with the REPL as the centre of the workflow and [[https://gitlab.com/emacs-geiser/geiser][Geiser]] driving everything:
  - The module does not need Guix. Where ~guix~ is installed it adds what only Guix can give (a Guix REPL, ~guix lint~, ~guix style~, Emacs-Guix's bindings); where it is not -- a Mac, say -- the same module is a complete plain Guile setup, with a ~guile~ REPL, the Guile compiler as the checker and Emacs' own indentation as the formatter. Nothing needs reconfiguring: it looks for ~guix~ and uses what it finds.
  - ~C-c g r~ starts or switches to the current project's REPL (a Guix REPL in a buffer that defines packages, a plain Guile one elsewhere), with the project root on Guile's load path and one REPL per project. ~C-c g R~ restarts it and ~C-c g s~ points it at the module of the current buffer.
  - Evaluation, loading and interruption from the buffer: ~C-c g e~ (definition at point), ~C-c g E~ (region or buffer), ~C-c g b~ (the whole file) and ~C-c g k~. ~C-c g x~ runs the file as a script with the project root on the load path, and ~C-c g d~ returns to Geiser's debugger after an exception.
  - Navigation from Geiser's own database, so there is no language server in this: ~C-c g g~ goes to a definition, ~C-c g h~ shows its documentation, ~C-c g c~ and ~C-c g C~ list callers and callees (a call hierarchy), and ~C-c g m~ lists the methods of a generic function. ~geiser-mode~ activates itself in Scheme buffers, its completion arrives through ~completion-at-point~ (and therefore through Corfu) and ~geiser-autodoc-mode~ puts signatures in the echo area.
  - Checking on save, from whichever tool is the authority: a Flymake backend runs ~guix lint~ on the package defined in the buffer (checkers, style, and anything else the installed Guix checks), a second one runs ~guix style~ on a copy of the buffer and reports the lines it would rewrite -- in any Scheme buffer, not only in package files, since drift in a Guix library file matters too -- and a third runs the Guile compiler (~guild compile~) in every buffer Guix is not the authority for, which is where the checking comes from without Guix: unbound and unused variables, unused modules and arity mismatches. The compiler runs on a copy of the buffer, so code that has been typed but not saved is checked too. ~C-c g L~ lints the buffer into a clickable compilation buffer (the hyperlinks Guix puts around file names are turned into real ones there), ~C-c g f~ formats it in place (re-indenting it with Emacs where Guix is not installed) and ~C-c g S~ applies one of Guix's styling rules (~inputs~, ~arguments~, ~git-source~) and reloads it.
  - ~guix-devel-mode~ is enabled in Guix buffers, which brings Emacs-Guix's own bindings: ~C-c . l~ to lint, ~C-c . b~ to build the package definition, ~C-c . s~ and ~C-c . d~ for its source, and ~C-c . u~ to insert a module at point. ~C-c g t~ runs the project's own test task.
  - Folding works in Scheme: a buffer is read as top-level forms, so each definition is a fold, collapsing the definition at point works from anywhere inside it, and the keys are the ones every other language uses (~C-c v c~ folds the definition, ~C-c v o~ and ~C-c v O~ unfold it, ~C-c v r~ reveals everything, ~C-c v t~ toggles and ~C-c v C~ collapses the file).
- Added a reusable way to turn an external tool into a Flymake backend (~heks-emacs-tool-diagnostic-backend~ and ~heks-emacs-tool-drift-backend~ in ~heks-emacs.el~). A *checker* that reports diagnostics and a *formatter* whose rewrites are the diagnostics are the two shapes a language tool has, and both are now a few lines of configuration. The process runs asynchronously with a pipe rather than a pty and with colour off, because a tool that believes it is talking to a terminal wraps file names in OSC 8 hyperlinks, which hides the ~FILE:LINE:COLUMN~ structure the parsers read; the output is parsed into file, line, column, severity and message; a diagnostic the tool could not attach to a line is reported from its error output instead of being dropped; and the buffer is checked through a temporary copy, so code that has been typed but not saved counts. The Guile module's two checkers are the first users.
- Added ~render.el~, which renders what one is reading as one HTML document, themed with the colours of the current Emacs theme and with no stylesheet to download: Markdown, Org (through Org's own exporter, body only), OpenAPI specifications and plain text each have a renderer, and the document is shown in EWW with ~C-c r p~ or in the browser with ~C-c r b~. ~C-c r r~ renders it again, ~C-c r e~ keeps it as a ~.html~ file next to the one being read, and ~C-c r m~ makes the preview follow the buffer, rendering again on every save. The predicates that choose a renderer return a yes or a no rather than the position a pattern matched at, so a caller can branch on them.
- Added ~openapi.el~, which reads, checks and explains OpenAPI specifications in JSON or YAML. ~C-c a v~ renders the specification the way Swagger UI would -- operations by tag, parameters and responses in tables, schemas listed, servers named -- in the same document ~render.el~ produces, and the operations are listed in the imenu menu under their tags. The document is checked as it is written, from the same table of rules: a path that is not a path, a key under a path that is not an operation, two operations sharing an identifier, a path variable nobody declares, a response code that is not one, a response without a description, a body with no shape, and a ~$ref~ that points at nothing. Each is a Flymake diagnostic where it is written. ~C-c a r~ calls one of the operations from the file itself (the server, the method and the parameters come from the document, and the answer lands in its own buffer) and ~C-c a b~ writes it as an Org request block instead.
- Added a formatter dispatcher (~heks-emacs-format-buffer~, ~C-c i f~) so that one key formats whatever buffer it is pressed in: a language module adds a predicate and a command to ~heks-emacs-format-dispatch~ and the buffer decides. Scheme is the first user, and its formatter is the one the Guile module already had, so ~C-c i f~ and ~C-c g f~ are the same command.
- Added golden renderings: ~test/fixtures/~ holds the documents -- a Markdown note and one OpenAPI specification written both in JSON and in YAML -- and ~test/golden/~ holds the HTML they rendered to, so a change in what the renderers produce arrives as a line-by-line diff of what they say now against what they said before, rather than as an invitation to look at a page and judge it. ~maak golden~ checks it and ~maak golden-update~ writes the pages again when the change is the one that was wanted. The two spellings of the specification have one golden page between them, which is what makes the two languages having to read alike a checked property.
- Added the keybindings reference (~docs/keybindings.org~), written from the configuration by ~maak keys-update~: the alphabet of action letters, the topic letters and what every key under them does. ~maak keys~ fails while it and the configuration disagree, so it cannot go stale.
- Added ~maak lint~ and ~maak verify~, and the two scripts behind them. ~lint~ reads every Elisp file of the configuration form by form and compares the module list in ~init.el~ with the modules that are there: a parenthesis that closed a macro too early, or a module renamed without its entry in the list, fails in a second without installing anything. ~verify~ installs the configuration first and then loads it in a batch Emacs the way Emacs does at startup, asserting what nothing else checks -- that every module is loaded (the feature is read out of each module rather than guessed from its name), that the tool-output parsers read the formats they claim to, that a diagnostic renders with its message where it belongs, that a fold covers a whole definition, that the documented keys are bound, that the type scale keeps its ratios and the separators keep their colour, and that the same setup still checks Scheme where Guix is not installed. It exits non-zero on failure.  ~maak keys~ reads the source for every binding -- including the ones that only take effect when a package loads, which a runtime dump of the keymaps cannot see -- prints the whole key tree under its topic letters and fails on a key that does two jobs, on a topic nobody documented and on a binding whose command does not exist; ~maak render~ checks the Markdown renderer on its own, as the string-to-HTML function it is.  ~maak check~ runs the six of them, in that order.
- Added Guix snippets for modules (~define-module~, ~use-modules~), G-expressions and imported modules, arguments, working inside phases (~substitute*~, ~which~, ~search-input-file~), inputs in the style ~guix style -S inputs~ produces, and ~replace~ with a body.
- A rendered document now shows its code in colour and can be navigated. A fenced block is fontified with the mode the fence's language names, each face it used becomes a class, and the stylesheet carries the colours of the *current* theme for it, so a README reads like the Emacs it was written in -- a keyword is the colour of a keyword, a string the colour of a string -- and the same document is readable in a light theme and in a dark one. A snippet is escaped before it is coloured, so a ~<~ in code is still a ~<~ on the page. Every heading is given an id and a list of contents is put between the headline and the body once a document has enough sections (~heks-emacs-render-toc-headings~, three by default), which is what makes an OpenAPI page -- an operation per heading -- navigable rather than only searchable. The stylesheet ends with a print block: page margins, one deck slide per printed page, and no navigation buttons or fixed controls on paper, so what is printed is what was read.
- Added ~treesit-grammars.el~, a batch script that builds every tree-sitter grammar this Emacs can be asked for -- Emacs's own recipes being the ones its mode files add as they load, plus the recipes of the languages Emacs ships no mode for (Kotlin, Scala, Nix) -- into ~~/.emacs.d/tree-sitter~. The configuration starts it in a batch Emacs of its own at startup, in the background, so that no grammar is ever cloned and compiled while a file is being opened: with ~treesit-auto-install-grammar~ at ~always~ a missing grammar was fetched without asking, but the first file of every language made the session wait for ~git~ and a C compiler, and a language no recipe was known for was a question on every visit. Only the grammars with no library here are built, a grammar that will not build is a line in the ~*heks-emacs tree-sitter grammars*~ buffer rather than the end of the ones after it, and ~M-x heks-emacs-treesit-install-grammars~ does the same work in front of you. Cloning a repository and compiling a grammar fails for reasons that are not about the grammar -- a clone that timed out, a checkout that was busy -- so every grammar is tried ~heks-emacs-treesit-attempts~ times (twice, by default) before anything is said about it: what is reported is a grammar that would not build twice, a language that worked on the second attempt says so, and a build that returned without leaving a library Emacs can load counts as a failure rather than as a grammar, which is what Emacs's warning-not-error answer to an unloadable library would otherwise have hidden.
- An Org note now previews the way a Markdown file does, through Org's own exporter. Org is asked for the *body* of the export and nothing around it, so a note arrives in this configuration's document, with its own stylesheet and its own list of contents -- Org's own list is asked for and dropped rather than left in beside it, which is where a page ended up with two -- and the headings it names are the ones the list links to, so every entry of that list is an entry that goes somewhere. The code in a note is coloured by Org through ~htmlize~, which the configuration now installs: where it is here the colours are written into the page as inline styles, because a preview carries none of Org's stylesheet and a class name with no stylesheet behind it is a block with no colour, and where it is not, Org is asked for plain text rather than for colours it cannot produce, which it answers with a warning on every export. The settings the export runs under are bound one at a time (`let*'), because the values of a `let' are all evaluated before any of them is bound, and the export is the last of them: with `let' Org was still writing its own contents list into the body.
- Added ~present.el~, which presents what one has written. An Org note is presented in Emacs itself (~C-c r P~), where ~org-present~ narrows the buffer to one heading at a time, scales the text up and takes ~SPC~ and the arrow keys for the next and previous heading (~q~ leaves it, and the mode line is hidden while the talk lasts, because it is not part of what is being shown). Anything else -- a Markdown deck -- is presented as a page in the browser (~C-c r d~): one ~section~ per slide, walked with the arrow keys, the space bar, Home and End or two buttons, with a counter that says which slide this is and what changed when it changed, and with the address bar keeping the slide number so a reload returns to it. A deck carries its own stylesheet and its own navigation and fetches nothing, so the exported file (~C-c r D~) opens from a ~file://~ URL on a machine that is not this one. ~C-c r n~ starts the next slide where point is, in the document's own way: a line of dashes in Markdown, a heading at the level the file's own slides are at in Org.
- Added the configuration's own test suite (~test/heks-emacs-ert.el~, run by ~maak test~ and therefore by ~maak check~). The other checks read this configuration and judge what it says; this one loads the modules and calls the code, which is the only way to find out that a function does what its docstring says: the renderer (fontification, escaping, anchors, the contents list, the stylesheet a theme produces), where a deck's slides begin in Markdown and in Org, the decks themselves (one section per slide, the navigation, the print styles, the export), the JVM build tools (which goal each tool calls, the nearest project, the wrapper over the system program), the formatter dispatcher, Terraform, Dired, and the key scheme's four tables. It runs in a batch Emacs with ~use-package~ stubbed out, so what is tested is the code rather than whether a package happens to be installed, and a test that needs something this machine does not have -- the ~terraform~ program, a YAML reader -- says so and is skipped rather than failing. The suite is also what found the faults below, and it covers the preview in the shape the fault was in: the document is rendered into the preview buffer and that buffer is then looked at, because EWW kills the buffer it renders from and the difference is invisible in a screenshot of a working preview.

*** Changed

- Window separators are now derived from the active theme instead of being left at the background color, so several buffers in one frame are clearly distinguishable in every palette. The color is applied to ~window-divider~, ~window-divider-first-pixel~, ~window-divider-last-pixel~ and ~vertical-border~, it is refreshed whenever a theme or the text scale changes, and it corrects the invisible separators that ~spacious-padding~ paints on purpose.
- ~window-divider-mode~ is now enabled with 2 pixel separators on the right and 1 pixel at the bottom.
- Org, Markdown, prose and code faces are now sized as multiples of the base font size. Changing the text scale with ~tekengrootte~ no longer compounds with the ~default~ and ~variable-pitch~ faces, so headings, body text and code blocks keep their proportions at every scale.
- Opening an Org or Markdown buffer no longer resets the global text scale to the regular size.
- The face helpers in the UI module are defined at file level, so Org, Markdown and theme hooks can call them even while ~tekengrootte~ is still being installed or loaded. The same guard now protects the Eglot Java bindings, which are applied after ~eglot-java~ really loaded instead of when it was merely activated.
- SQL buffers now start Flymake so that ~sql-lint~ actually runs, instead of only being registered as a backend.
- The Scheme, Guile and Guix configuration moved out of ~dev.el~ into ~guile.el~, where the REPL engines, the checking and formatting backends and the keys live together. ~dev.el~ keeps the general-purpose development tooling.
- Geiser is now the single REPL client and is configured for project work: one REPL per project, the project root on Guile's load path, the REPL in another window, full backtraces for failing evaluations and warning levels high enough to report unused variables and unused modules, both at the REPL and in the buffer. ~geiser-mode~ now turns itself on in Scheme buffers, so completion, eldoc and the debugger are there the moment a ~.scm~ file is opened.
- Removed [[https://codeberg.org/abcdw/guile-ares-rs][Ares RS]] and [[https://github.com/abcdw/emacs-arei][arei]], together with ~heks-emacs-scheme-repl-backend~, the ~ares-nrepl~ server management and the keys that belonged to them (~C-c g a~, ~C-c g A~). Geiser covers the same workflow without a second protocol, a second session concept or a server that has to be built before the first evaluation.
- Folding is now one set of keys (~C-c v~) on top of [[https://github.com/jamescherti/kirigami.el][kirigami]], which knows which engine a buffer has -- Tree-sitter, Hideshow, Outline, Org or Vdiff -- instead of the Scheme module binding its own pair. kirigami answers with the first engine whose mode is on, and ~outline-minor-mode~ is on in almost every buffer here, so ~kirigami-fold-list~ is reordered to put Hideshow first: in the buffers where Hideshow was turned on deliberately, it is what ~C-c v c~ folds, rather than headings a Scheme file does not have.
- The key scheme now says what keeps Org's statistics cookies out of the way of the global ~C-c #~ keys: the command moved to ~C-c C-#~, which is documented as a topic of its own (~C-#~) rather than reported as an undocumented one.
- The action letter ~i~ means one thing again. It had come to mean three: ~C-c i i~ went to the implementation, ~C-c g i~ interrupted a running Guile evaluation and ~C-c s i~ inserted a snippet. ~i~ is now "insert" everywhere, and the two odd ones out moved to the letter that already means what they do -- the implementation is ~C-c i g~ in a family where ~g~ goes to a definition, and the interrupt is ~C-c g k~, where ~k~ is the letter that stops a process just as it stops a language server under ~C-c i k~.
- Two more keys moved to letters the scheme already defines: the Mermaid documentation is ~C-c C-d h~ rather than ~C-c C-d d~ (~d~ is the debugger and a diff) and Eglot reconnects with ~C-c i R~ rather than ~C-c i x~ (~x~ runs a script, ~R~ restarts, as it does for the REPL), and the methods of a generic function are on ~C-c g m~, the letter of every menu, rather than on a ~u~ that meant nothing.
- ~maak check~ now runs the configuration's own test suite as well, between the renderer's own checks and the golden renderings: ~lint~, ~keys~, ~render~, ~test~, ~golden~, ~verify~. The suite needs nothing installed -- it loads the modules out of ~src~ with ~use-package~ stubbed out -- so it is the one check that can be run while the configuration is being edited.
- EMMS is gone, and with it the music directory. The ~C-c M~ topic keyed a library, an MPD daemon and a playlist, and none of that is part of this configuration any more: ~C-c M~ is not bound at all, and ~music.el~ keeps what is about music itself -- a fretboard to look at while a chord is written down, and the player that plays the file at point -- with no library to point at, no daemon to keep running and no keys of its own under ~C-c~. The ~heks-emacs-music-directory~ setting went with them, so the line a bridge had been setting (~heks-emacs-ews-music-directory~, a name this configuration never defined) named a variable that does not exist, and nothing in the configuration reads a music directory now. ~C-c m~ is untouched: it is maak, the task runner, and it was only ever the capital letter that meant music.
- Topics that key something which is not an action no longer have to borrow an action letter for it. A font size, *whose* configuration is being reconfigured and the journal entry for today are named by their own letter in ~heks-emacs-key-letters~, and the audit now reads both tables: a key whose letters are in neither fails the build, instead of being reported as a note nobody actions. The key tree printed by ~maak keys~ shows the meaning of every key, and the whole scheme is written out as a document (~docs/keybindings.org~) from the tables and the bindings themselves, so the reference cannot stop being true while ~maak check~ is green.

*** Fixed

- Fixed the preview and the OpenAPI view, which failed with ~Wrong type argument: stringp, nil~ instead of showing anything. EWW renders a document out of the buffer its retrieval put it in and *kills that buffer* when it is done -- ~eww-render~ is the callback of a retrieval, and the buffer is the retrieval's own -- so a preview that asked EWW to render from its own destination buffer was left holding a dead one, and the ~pop-to-buffer~ that followed died on it. A preview now answers EWW the way a retrieval would (the content type, then the document, in a buffer of its own) and EWW renders that into the preview buffer, which is still there afterwards and still holds the page. ~maak verify~ asks for a preview and looks at the buffer it landed in, so this cannot come back unnoticed.
- Fixed the settings the bridge gives not reaching the modules that read them. The installed configuration defines the customization variables in ~heks-emacs.el~, gives them their values in the bridge next to it (which fonts, which theme, where the notes are) and loads the modules after that -- but the bridge was being loaded *after* the modules, so a module read a setting while it was still ~nil~ and was configured wrongly whatever the setting said a moment later. ~org-roam~ is where it showed: ~org-roam-directory~ was built out of a ~nil~ and stopped the configuration while it loaded, which is why org-roam has not worked. The bridges now load before the modules, and ~heks-emacs-notes-roam-directory~ answers ~nil~ -- rather than a path -- when no notes directory has been set, in which case org-roam is loaded but not started and the variable to set is named in the echo area instead.
- Fixed the startup error that stopped the configuration while it loaded: ~Wrong type argument: listp, #(" ■ Warning (emacs): Duplicate item ID queued: org-present" ...)~. ~org-present~ was declared twice -- by ~org.el~ and by ~present.el~ -- and elpaca answers a package that is queued twice with a *warning string* where a queued item was expected, which the code that walks the queue then tried to read as a form. The declaration now lives only in ~present.el~, the module that presents things, and ~org.el~ says so where its own declaration used to be. ~maak verify~ loads the installed configuration the way Emacs does at startup, so a module that cannot be loaded -- and a second declaration stops the loading -- fails the build.
- Fixed the contents list of a document whose headings arrive with ids of their own. The id was kept in the page and thrown away in the list, which generated a slug out of the heading's text instead, so every link from the contents list of an OpenAPI page -- each operation named after its method and its path -- pointed at an anchor that did not exist, and following one went nowhere. A heading's own id is now the one the list points at, which is also what a link from elsewhere in the document needs.
- Fixed the document stylesheet dropping every face attribute that is not a colour. ~heks-emacs-render--face-attribute~ passed only strings and numbers through and answered ~nil~ for the rest, so the weight, the slant and the underline of a fontified face were discarded and the rules meant to carry them were written empty: highlighted code came out coloured but unemphasised, and font-lock's keyword and function-name faces lost the weight that makes them stand out. A face's attributes are now read as the face states them, so both branches of the stylesheet -- the colour and the emphasis -- are written, and a face that declares no colour still gets the plain rule that leaves it inheriting its surroundings.
- Fixed the OpenAPI renderer for YAML specifications, which came out as an empty page. ~yaml-parse-string~ hands back what a scalar *looks* like rather than what a specification means -- a bare key arrives as a symbol, so every lookup of ~paths~ or ~get~ missed and nothing was rendered, and a response written ~200~ arrives as the number 200, which stopped the rendering with ~Wrong type argument: stringp~ as soon as it was escaped. Mappings are now read once through the string their keys are written as, and everything that is shown or searched for goes through ~heks-emacs-openapi-text~, so a YAML specification and the same one in JSON render as the same page -- which is now checked, in ~maak verify~ and again as a golden rendering.
- Fixed ~required: false~, which was rendered as ~yes~: both parsers are asked for the symbol ~:false~ where a document says ~false~, and a symbol is a true value in Elisp. Booleans are read through ~heks-emacs-openapi-yes-p~, so a parameter that is not required says nothing rather than the opposite.
- Fixed the Markdown renderer leaving a list unclosed when the next block was not a list, or when the list ended the document: the closing pass only closed lists nested *deeper* than the current indentation, so a heading after an ordered list ended up inside the list. A block that is not a list now closes every list, which is what a browser does with the same document.
- Fixed the order of what the OpenAPI page shows: a mapping has no order of its own, and the one a hash table iterates in was reaching the page, so the operations, the media types of a body and the schemas could come out in a different order from one run to the next. They are read in a defined order now, which is what lets the rendering be compared with a file.
- Fixed the ~ef-autumn~ palette overrides, which were assigned to a non-existent ~ef-autumn-palettes-overrides~ variable and were therefore silently ignored.
- Fixed the ~heks-emacs-standup-people~ customization type, which warned about a ~list~ without arguments.
- Fixed a startup error in ~dev.el~: ~fancy-compilation-mode~ was called from an ~after-load~ handler for ~compile~, which fails whenever ~compile~ is loaded before Elpaca has activated the package (an early ~require~, such as Flymake's, does that). The package is now loaded on demand.
- Fixed the way diagnostics were built for Emacs 31 and later, where a diagnostic carries an origin, a code and a message rather than a bare string. A message put in the wrong slot still rendered, but with the separator of the missing headline in front of it; the tools are now named as the origin, the way Eglot names its server, so a diagnostic reads ~guix lint : ...~ and its message is the message.
- Fixed the ~C-c g l~ binding (~guix-package-location-on-mark~), which required ~guix~ and ~guix-package~ unconditionally and so failed on a machine without Emacs-Guix. It now says what is missing, and asks for a selected package name instead of reading whatever happens to be between point and the mark.
